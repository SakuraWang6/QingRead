# 追更、换源与下载

[文档导航](README.md) · [账号同步](cloud-sync.md)

0.9 在 iPhone、Web 和 Android 提供相同的章节工作流。追更状态和下载任务保存在当前设备的当前账号内；书源选择及阅读位置继续随书架同步。章节缓存不上传服务器。

## 追更

书架的刷新按钮检查已收藏的联网章节书，有新增时显示「更新 N 章」。iPhone 也支持书架下拉检查；Web/Android 使用刷新按钮。打开书架或回到前台会尝试自动检查，读到最后一章时也可继续检查最新目录。

自动检查每本至少间隔 15 分钟，手动检查至少间隔 60 秒，失败也会冷却。每次只检查书架内启用的来源，顺序请求，不进行服务器全库轮询或推送。Web 页面和 iOS App 关闭时不保证检查更新；这里的提醒是应用内角标。

已有缓存目录作为初次基线；从未获取过目录时只建立基线，不把整本未读章节算作新增。通过旧末章 ID、唯一标题定位新追加的章节；目录重排且无法确认时不猜测新增数量。请求失败保留旧目录、正文与提示，读到新增章节后消减角标。

## 换源

书架中章节书的详情和阅读菜单提供「换源」。候选只包含已启用来源的同名书，双方有作者时还需要作者匹配；EPUB/PDF/TXT 等整本文件不执行章节换源。

选择候选后先获取新目录，按唯一章节标题或唯一章节编号匹配，支持常见中文章号。匹配不确定时自行选章；确认目标章节后再切换。新目录和目标正文成功落盘前保留旧书架、位置与缓存；失败可以重试，关闭面板会取消尚未提交的请求。

换源保留逻辑书籍 ID 和加入书架日期，按章内阅读比例映射到新正文，避免把原来源的绝对字数偏移直接用于不同正文。由于来源排版和文字可能不同，换源后页码可以变化。新的位置以正文 UTF-16 偏移同步，原生排版中的章节标题不计入该偏移。

同步服务拒绝旧来源的进度覆盖新书源；并发换源需要当前修订号。另一设备收到来源变化后失效旧目录、正文和下载请求，活动阅读器重载新来源。建议各设备均更新到 0.9，旧客户端不具备新的本地缓存失效逻辑。

## 下载管理

从详情或阅读菜单选择「下载章节」：

- 后续 50 / 100 章：从当前章节开始，已缓存内容计入完成并跳过请求。
- 整本：下载当前已获取目录内的全部章节。
- 自选范围：界面输入从第几章至第几章，包含两端。

书架和章节目录提供「下载管理」，集中查看进度、暂停、继续、取消及失败重试。开始下载会把书加入书架。下载使用单任务队列，每章有限重试；重复添加相同的活动范围复用任务。Web 保留最近 20 条精简的结束记录。

任务进度持久化，重开后未完成任务为暂停状态，点击继续恢复。进入后台时会暂停；iOS、浏览器或 WebView 可能中止后台执行，不能承诺关闭应用后继续下载。删除书籍、禁用来源、清理缓存或切换账号，会停止对应的旧任务，已下载的章节在未清理时仍可离线读取。

每个账号和设备的任务独立；换设备后可重新选择要缓存的范围，不会把另一台设备的下载队列自动搬过来。整本电子书的原文件下载与云文件同步继续使用现有流程。

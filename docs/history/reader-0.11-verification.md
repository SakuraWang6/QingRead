本文保留 0.11 发布及鸿蒙首版开发阶段的验证事实；当前状态见[验证记录](../verification.md)。

更新于 2026-10-23（Asia/Shanghai）。已发布客户端维持 **0.11.0**，API 维持 **0.10.0**。鸿蒙版源码开发与资源检查见下节；尚未替换已发布的三端或服务器。

## HarmonyOS 首版开发

新增 ArkTS Stage / ArkWeb 工程，目标 SDK 26.0.0 Release，最低兼容 HarmonyOS 5.0（API 12）。源码版本为 0.11.0 / versionCode 1，包含固定来源离线资源、系统返回、文件选择及只读系统版本接口。通知、后台下载、原生听书、安全持久登录和文件导出尚未接入，不将 Web 功能复用描述为已完成系统适配。

- 共用 Web 测试 228 项通过，4 项实时来源检查跳过；TypeScript 与根路径生产构建通过。
- 17 项发布元数据测试、4 项离线资源打包测试、4 组原生地址策略测试通过。
- 213 个实际 Web 资源已离线打包，逐文件核对 SHA-256；脚本拒绝符号链接、未允许的文件类型及签名文件备份后缀。
- 上述原生策略测试在宿主 Node 中执行。另使用官方 CLT 26.0.0.851、SDK 26.0.0、Hvigor 6.26.8、Node.js 24 与 JDK 21 实际编译生成未签名 HAP，并安装、运行于官方 HarmonyOS 7.0.0 / API 26 手机模拟器。
- 模拟器中联网分类、可见四张真实封面、样例滑动翻页与中间菜单、系统返回通过；修正缺少 `GET_NETWORK_INFO` 导致的错误离线提示。覆盖安装后样例书籍及 79% 阅读位置保留。
- 通过模拟器浏览器下载本机自建样例，再经系统选择器分别导入 EPUB、PDF、TXT；正文可读，PDF 实际渲染完成，TXT 可跨章翻到正文。本轮没有放宽文件访问、绕过 TLS 或修改模拟器存储权限。
- 发现并修复共用 Web 的重复滚动锁：父层与阅读器分别恢复 `body.style.overflow`，退出阅读后会残留 `hidden`。统一持有者管理后，新增 5 项生命周期回归；最终 HAP 中分别验证退出 TXT / PDF → 设置滚动 → 关于页，均通过。关于页显示系统安装身份 `HarmonyOS 0.11.0 (1)`，服务端未发布鸿蒙信息时正确显示未发布。
- 没有已签名 HAP、真机或旧版鸿蒙运行结论，最低 API 12 仍需对应系统实测。
- 本轮未部署服务端、修改路由、数据库、容器或 iPhone 签名续期配置。

## 关于与更新

三端包含真实版本信息、手动检查、离线更新日志与说明、主动反馈入口和本地许可。共用说明源为 `App/Resources/AppInfo.json`，根 `LICENSE` 与原生许可资源逐字节一致，第三方许可单独保留。

公开静态清单与 API 服务版本分开。失败、超时、取消、无效清单均不会显示“最新”；版本与构建号按数值比较，较低版本不会触发更新。版本请求不附账号凭据、Cookie 或私人诊断。

- iPhone 使用实际 Bundle 版本；发现更新时提示现有 Mac 签名流程，不承诺应用内安装。
- Android 使用系统安装版本与构建号；仅较新版本有已发布、同源 HTTPS、固定版本 APK 时显示下载。覆盖安装仍由系统确认。
- Web 手动检查 worker 与清单，共用原有更新提示；新资源就绪并由用户确认后才激活。激活入口再次核验版本，失败保留当前页面。

真实浏览器在 390 × 844 验证关于页、更新日志、使用说明和反馈内容；反馈复制只包含版本与平台。已从运行中的旧 0.10.1 PWA 点击更新到 0.11.0，原有两本书架保留，线上手动检查成功。离线资源导入与 Vite 文件访问边界另有定向测试。

- Swift：21 项 XCTest、38 项 Swift Testing 通过，共 59 项。
- Web：212 项通过、4 项实时来源跳过，其中 23 项为本轮关于、版本身份、清单、更新协调器及资源边界测试。
- 发布元数据：14 项 Python 测试通过，覆盖版本一致、许可一致、无效 APK、地址约束与生成原子性。
- TypeScript、根路径 Android Web 构建、`/qingread/` Web 生产构建通过。
- 本机仓库根 context 的 Docker `build` 阶段构建通过；默认拒绝的 `.dockerignore` 不包含私有配置、备份或签名材料。未在生产服务器构建镜像。
- iPhone 真机与模拟器构建、严格签名检查通过，专用模拟器截图确认版本 0.11.0 / 15 与五个功能入口。随后本机完整十屏预览通过，原有 storage、cover、AI、speech、reader、段落命中及前后跨章暖布局复用断言全部保留并通过。

应用实现与分发包对应源码提交 `bba781c`；`3ea5874` 仅补充 CI 的模拟器冷启动诊断、有限恢复及共享声明输入触发项，不改变客户端代码。最终 [Web CI](https://github.com/SakuraWang6/QingRead/actions/runs/39958806313)、[Android CI](https://github.com/SakuraWang6/QingRead/actions/runs/39958806315)、[原生 Verify CI](https://github.com/SakuraWang6/QingRead/actions/runs/39958806348) 均通过，包含全部十屏预览、阅读及跨章诊断。

原生前两次 CI 均在安装 App 之前的 `simctl bootstatus` 超时，不能据此归因于阅读器。预览脚本保留所有阅读断言，增加 runtime/device 与超时输出，等待 300 秒，且仅第一次启动超时才对同一模拟器恢复一次；第二次失败仍退出。本机真实冷启动检查通过，恢复编排的 6 项私有诊断测试通过。 新脚本的首次云端执行成功启动系统并完成 library/search/sources，但 reader 未产生诊断日志，未完成全套预览；相同脚本与客户端在本机十屏流程全部通过。最终相同代码重跑通过全部预览与阅读诊断，启动日志和每轮工件均已保留；未将间歇失败归因于特定业务代码。

独立自动续签运行副本及其已安装版本基线均同步为 **0.11.0 / build 15**。新旧描述文件同源，私有签名配置、原有签名备份及锁文件保持完整；LaunchAgent 仍每 14,400 秒检查。加载后因尚未进入续签窗口而按规则跳过，退出码 0；本轮没有强制续签或再次安装手机。

## Android 分发

公开 CI 使用临时调试签名。个人升级包在私有环境替换同一源码构建的完整 213 个 Web 文件，并沿用原固定升级证书：451 个非 Web、非签名条目的内容与压缩方式均与 CI 一致，旧 Web 资源无残留。包名、0.11.0 / code 11、v2/v3 签名及 ZIP 检查通过。

227 个未压缩条目的实际数据偏移均通过四字节对齐检查，无原生 `.so`。本机未安装官方 `zipalign`，未声称运行该工具。公网 latest 重新下载的 **7,243,688 bytes** 与已验签包 SHA-256 完全一致：`cc504cf37bf79836fc2e15985d922b238f2531abd8fac27ffe54c1167b15f27f`。

服务器先核对真实 APK，再原子发布包含其固定版本下载路径、大小与哈希的清单。公开源码中的 generic 清单仍不含下载承诺。

## 服务器与平台边界

Web 已发布至独立静态目录 `qingread-0110-20261023`，保留旧版并原子切换清读链接。版本 JSON 单独增加 `no-store` 和无凭据跨域响应头，Caddy 经 validate 后热加载，并保留配置文件 inode 与备份；未改变其他路由或账号 API 鉴权。

即时部署前后的 **7 个容器** ID、镜像、启动时间、重启次数、OOM、健康状态和端口均一致；Compose 配置未改。清读页面、PWA 资源、API、课程入口正常，根地址仍为空白 404。核对时可用内存约 626 MiB，磁盘剩余约 20.02 GiB。未重启业务容器或改数据库。

Android 没有真机或模拟器运行结论；iPhone 的触摸体验仍需实际使用反馈。本轮不扩大通知、后台下载或听书能力，既有边界见[平台工作流](../reading-workflows.md)。客户端更新的部署与安装约束见[关于清读与更新](../app-updates.md)。

# iPhone 小说阅读器调研与首版取舍

调研日期：2026-10-20（中国标准时间）。目标是个人使用的原生 iPhone App：免费、没有广告、直接输入书名或作者搜索，不要求逐本寻找网址。

## 结论

这类产品主要有两条路线：一是浏览器搜索后提取网页正文，二是导入站点规则后并行搜书、换源。用户需要第二条路线的操作体验。书源是否可持续维护，比阅读器功能数量更决定能不能长期使用。

建议首版完成“搜书 → 目录 → 阅读 → 书架继续读 → 换源”的闭环，内置两个真实可用的经典文本来源，再提供自定义站点规则。经典文本能验证阅读链路，但不能宣称已覆盖当下流行网文。热门书覆盖需后续用用户实际看的书单验证。

证据分级：下表中的功能和费用为公开声明；本次没有在 iPhone 上安装这些 App，也没有测评它们的广告频率、耗电、翻页速度或全部书源成功率。本文后半部分明确记录了本机发出的真实 HTTP 请求结果。

## 两个能接通的首版文本来源

### 1. 中文维基文库：真正的远程搜索、目录和章节接口

使用公开 MediaWiki Action API，无需 API key。基础地址为 `https://zh.wikisource.org/w/api.php`。[MediaWiki 官方搜索文档](https://www.mediawiki.org/wiki/API:Search)说明 `action=query&list=search`、`srsearch`、命名空间和分页参数。

本次从本机发请求，均返回 HTTP 200：

| 用途 | 参数（需 URL 编码） | 本次结果 |
| --- | --- | --- |
| 搜索 | `action=query&list=search&srsearch=紅樓夢&srnamespace=0&format=json&utf8=1` | 返回 895 个匹配，首条标题“紅樓夢”，有 pageid、摘要和时间 |
| 目录 | `action=parse&page=三國演義&prop=links&format=json` | 返回书内子页面链接，包含“序”“凡例”“三國演義/第001回”等 |
| 正文 | `action=parse&page=三國演義/第001回&prop=text&format=json` | 返回真实首回 HTML，包含“三结义”等首回正文 |

实现注意：

1. 搜索结果也有评论、消歧义和单章，不等同于每条都是完整书。应过滤命名空间、对根书页排序，显示来源和版本。
2. 目录不能不加判断地把所有链接都当章节。只保留选定书页的子页，并处理重定向、分页、不同作品的目录布局。
3. `parse.text` 包含导航、样式及附注，正文需提取文章区域并移除 `script/style` 和导航块。本次简单去 HTML 标签后仍看到了 CSS，因此不能仅用一个正则清理。
4. 中文查询涉及繁简、旧名和版本，可对搜索关键词做繁简转换或补充查询。不要把不同版本的第 10 章直接等价。
5. 为请求设置明确 User-Agent、超时、取消、缓存；实际可达性还需在用户手机网络上验证。本次连接成功不代表所有地区长期可达。

适用范围：中文经典、历史文本等。它不是流行连载小说搜索接口。

### 2. 开源古典小说数据集：本地搜目录，按章读取真实文本

[luoxuhai/chinese-novel](https://github.com/luoxuhai/chinese-novel)提供图书信息 JSON 和按数字命名的章节 HTML，仓库声明 [MIT](https://github.com/luoxuhai/chinese-novel/blob/master/LICENSE)，已于 2022 年归档。MIT 是仓库作者的许可声明，古典原文、具体整理版本、简介与封面的授权需要分开确认；首版应保留来源署名，避免搬用未核对的现代简介或封面。内容结构固定，可固定到具体提交并把目录随 App 打包，降低依赖站点搜索接口的成本。该源没有远程小说搜索 API；搜索是对已内置书名和作者目录进行本地匹配，必须如实标注。

原始资源基址：`https://raw.githubusercontent.com/luoxuhai/chinese-novel/master/`。下列路径已经真实请求并返回 HTTP 200：

| 相对路径 | 本次确认 |
| --- | --- |
| `resources/历史演义/三国演义/info.json` | 书名、作者罗贯中、120 个目录标题 |
| `resources/历史演义/三国演义/0.html` | 首回真实正文，4,875 字符，以 `<br>` 分段 |
| `resources/鬼怪神魔/西游记/info.json` | 书名、作者吴承恩、101 个目录标题 |
| `resources/世态人情/红楼梦/info.json` | 书名、作者曹雪芹、120 个目录标题 |

可复核的完整原始链接：[三国目录 JSON](https://raw.githubusercontent.com/luoxuhai/chinese-novel/master/resources/%E5%8E%86%E5%8F%B2%E6%BC%94%E4%B9%89/%E4%B8%89%E5%9B%BD%E6%BC%94%E4%B9%89/info.json)、[三国首回 HTML](https://raw.githubusercontent.com/luoxuhai/chinese-novel/master/resources/%E5%8E%86%E5%8F%B2%E6%BC%94%E4%B9%89/%E4%B8%89%E5%9B%BD%E6%BC%94%E4%B9%89/0.html)。维基文库复核链接：[搜索紅樓夢](https://zh.wikisource.org/w/api.php?action=query&list=search&srsearch=%E7%B4%85%E6%A8%93%E5%A4%A2&srnamespace=0&format=json&utf8=1)、[三国目录](https://zh.wikisource.org/w/api.php?action=parse&page=%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9&prop=links&format=json)、[三国首回](https://zh.wikisource.org/w/api.php?action=parse&page=%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9%2F%E7%AC%AC001%E5%9B%9E&prop=text&format=json)。

数据契约由仓库 README 给出：`info.json` 包括 `name`、`author.name`、`intro`、`catalogues`、`catalogueTotal`；正文文件从 `0.html` 递增。实现时以目录数组和实际章节存在性为准，不硬编码每本书的回数。URL 路径必须按 UTF-8 编码。

本次 GitHub 目录树 API 返回 403 限流，因此运行时不宜依赖匿名 GitHub API 来枚举书目。可维护小型书目清单、固定数据版本、按需缓存章节并保留来源与许可说明。Raw 域名在用户网络上的可达性仍需真机验证；可把少量已核对文本作为离线样本随包提供。

适用范围：经典小说和首版链路验证。不会自动发现最新网文。

### 暂不作为默认依赖：Gutendex / Project Gutenberg

[Gutendex 官方文档](https://gutendex.com/)支持 `/books/?languages=zh&search=...`，返回书名、作者及格式 URL，是可扩展候选。但本次请求先 15 秒超时、再收到 HTTP 503，不能把它写成已验证稳定的第二源。服务作者也建议长期使用自行部署。

[Project Gutenberg 自动访问规则](https://www.gutenberg.org/policy/robot_access.html)要求自动化使用其指定目录/镜像/采集通道；不要把网站搜索页面抓取当作长期默认 API。本次网页请求还遇到了证书链错误，未关闭证书校验来绕过问题。

## 首版产品和实现取舍

| 优先级 | 采用 | 原因 |
| --- | --- | --- |
| P0 | 原生 SwiftUI；书架、搜书、书源三个主要入口 | 用户意图很明确，不需要先搭账号或书城 |
| P0 | 输入书名/作者即可搜；来源陆续返回；可以取消；单源失败不抹掉其他结果 | 搜索等待时间和失效书源是同类产品核心摩擦 |
| P0 | 目录、正文、阅读进度持久化；缓存已读章节；字号和日夜主题 | 首先验证每天能否舒服地接着读 |
| P0 | 所有页面无广告、无会员墙、无追踪 SDK | 用户的首要痛点 |
| P0 | 两个真实经典源；自定义站点规则的导入/启用/禁用 | 装好即可搜，同时为后续站点扩展留入口 |
| P1 | 同书多源合并、换源候选、章节标题匹配 | 先保存原进度，匹配不确定时让用户选章；避免换源后跳错章 |
| P1 | 显示书源状态、最近成功时间、错误和规则版本 | 不让“没搜到”和“来源挂了”变成同一个空白界面 |
| P1 | 可导出书架与进度、本地 TXT | 数据可恢复，网络不佳仍可阅读 |
| 后续 | Legado 复杂 JavaScript/登录兼容、TTS、EPUB、WebDAV、自动推导任意网站 | 范围大，首版不承诺全部兼容 |

MVP 验收应该能实际做到：输入“三国演义”得到真实结果、打开目录、读真实正文、加入书架、退出后恢复、断网读取已缓存章；在一个来源失败时仍展示另一个来源的结果；导入自定义规则出现明确成功或失败信息。不能用静态假书架和虚构搜索结果替代这个闭环。

## 安装与后续验证

当前先交付可在 Xcode 打开的源码和原生项目，模拟器构建不需要购买开发者会员。安装真机仍需要用户的 Apple 账号选择 Team 和设备信任步骤；本次调研不触碰其账号。

后续最有价值的验证：让用户给出 3–5 本平时看的书名，确认其希望使用的站点，再核对对应来源的可用性、目录规则和内容质量。现有一手证据不足以承诺“全网任意小说永久免费无广告”。

## 收到实际书单后的补充验证

用户给出《超神机械师》和“真游戏也太真实了”，第二本按《这游戏也太真实了》核对。首版随后增加两个声明式网络小说来源，查询走站内真实 GET 搜索，没有把两本书的详情链接硬编码成搜索结果。

| 来源 | 站内搜索与解析 | 本次核实 |
| --- | --- | --- |
| 笔趣阁 · biequgei | `/search.html?keyword={query}`；`.txt-list li` 搜索结果、`.s2 a` 书名链接、`.s4` 作者；目录只取完整目录块，正文 `.read-content` | 两本通过实际 Swift URLSession 的搜索→目录→首章链路。《超神》1493条目录、首章102段；《这游戏》1106条目录、首章98段。目录包括完结/番外标题，但没有逐章核对全书。连续两次查询曾短暂返回空结果，稍后单独重试恢复，原因未确定 |
| 我书阁 | `/search.html?keyword={query}`；`.search-result-item`、`.book-info-title a`；完整目录 `.chapter-list-container ol a`，正文 `#TextContent` | 《超神机械师》实际 Swift 引擎得到1463章目录、首章97段；《这游戏也太真实了》本次真实搜索没有命中 |

一手入口：[biequgei](https://www.biequgei.com/)、[我书阁](https://www.woshuge.com/)。这些是第三方网站，网站自行描述的作品状态和章节完整性不能当成客户端保证；保留来源名称和原始网址以便核对。这里只保存适配规则与技术验证结论，不把完整小说网页、正文或站点脚本提交仓库。

另一个已检验候选“沧海书阁”两书搜索、目录和首章也可读取，但《这游戏》只见100条目录，《超神》约1121条，暂未设为默认来源。当前适配不绕过登录、付费或人机验证；遇到限制由正常请求失败信息反馈给读者。

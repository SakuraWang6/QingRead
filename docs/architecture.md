# 清读架构

[文档导航](README.md) · [开发与验证](development.md)

更新于 2026-10-21。当前 iPhone 为 0.8.2/build 10，Web/API 与 Android 为 0.8.1/versionCode 6。

## 客户端与服务端

清读有两个界面实现：iPhone 使用 SwiftUI 与 UIKit，Web 使用 React 与 TypeScript，Android 通过 Capacitor 8 复用 Web 界面。三端都支持书架、搜书、分类、章节阅读、文件导入和可选账号同步；听书与系统集成的差异见 [Web](../web/README.md)、[Android](../web/android/README.md) 和 [离线语音](offline-voice.md)。

| 模块 | 职责 |
| --- | --- |
| `Sources/ReadingCore/` | Swift 书源模型、网络传输、搜索、目录与正文解析、整本书库及导入契约 |
| `App/` | 原生界面、持久化、阅读排版、封面缓存、语音和账号同步 |
| `web/src/` | Web/Android 界面、IndexedDB 存储、浏览器阅读器与同步客户端 |
| `web/server/` | Node 24 书源 API、账号会话、SQLite 同步和私有云文件 |
| `web/src/shared/` | Web/API 共用的书源、类型与同步协议 |
| `web/android/` | Android 壳、返回键、安全区、KeyStore 与电量接口 |

Swift 与 TypeScript 书源引擎分别维护。iPhone 直接请求来源；Web/Android 通过自建 Node 服务请求已登记的来源。账号同步是可选服务：未登录时本地阅读，登录后才同步个人书架和文件。

## 来源与搜索

来源将搜索结果、目录和正文映射成统一的 Book / Chapter / ChapterContent，界面不包含网站 CSS 选择器。多来源并发查询，失败来源单独反馈；取消和新查询会阻止旧结果覆盖当前状态。推荐与分类来自来源公开书目，不是个性化模型或全网排行。

iPhone 支持导入简单的声明式 JSON 规则；Web/Android 由服务端维护来源，页面上的规则检查不会安装远程来源。两套引擎均不承诺兼容 Legado 的完整脚本规则，不绕过登录、付费、验证码或 DRM。格式和真实来源检查见 [书源说明](sources.md)。

## 阅读与缓存

原生 `ReaderDocument` 用统一 UTF-16 文档描述章节，`ReaderCanvas` 的 TextKit 连续容器决定实际页界。同一文字锚点用于翻页、滚动、位置持久化与语音定位。0.8.2 在阅读空闲时准备已缓存的相邻章布局，边界页与本章页面共用翻页动画；未缓存内容仍需等待网络。

Web 通过当前视口和排版设置分页，重新排版时恢复文字位置。Android 使用同一阅读器。中央点击显示或隐藏控制栏，翻页自动关闭控制栏；iPhone 提供边缘返回手势，Android 接入系统返回键。

整书页码与进度条优先使用已测量页数，再按缓存正文和当前排版估算其余章节。字号、视口和缓存变化可能改变总页数；跨端同步保存 UTF-16 文字位置，不能把某台设备的页码直接用于另一台设备。PDF 保留原始版面，独立按原始页码保存位置。

书架、设置、位置、逐章阅读进度与正文缓存分开持久化。目录只显示实际记录的逐章最大进度，不推断前面的章节全部读完。阅读时顺序预读后续 10 章；清理缓存和移除书籍使用任务取消与世代校验，旧响应不得回填已清理的数据。

`BookCoverCache` 管理原生内存与磁盘缩略图，必要时查询同一作品的封面元数据；Web/API 另有公共封面缓存。封面来自来源或导入文件，缺图使用书名排版，不从其他作品猜图。缓存可以重新生成，不能与用户原文件混为一谈。

## 账号与文件同步

客户端按账号隔离本地存储，登录或切换账号不会自动合并未登录书架。服务端通过 Bearer 会话确定账号归属，使用 SQLite 保存书架与变更记录，原文件放在私有目录；书籍 ID 或文件哈希本身不提供访问权限。

书架操作持久化排队并按操作 ID 去重，服务端修订号处理分页与删除墓碑。阅读位置采用时间戳和 UTF-16 锚点；文件使用 SHA-256 校验并按需下载。章节缓存与语音模型不上传。身份、冲突、配额和备份边界见 [云同步](cloud-sync.md) 与 [服务端说明](../web/server/README.md)。

## 听书与依赖

`ReaderSpeechController` 管理系统朗读、音频会话、锁屏控制和播放意图。切章、停止和退出使用取消边界，过期回调不能重新启动播放；系统语速或音色变化从当前文字位置继续。

原生 Melo 与 Kokoro 经固定版本的 sherpa-onnx 在设备端合成。模型下载需用户主动触发，逐文件检查大小与 SHA-256，整批通过后才可选用；推理在后台串行队列完成，准备后续短句并缓存 WAV，语速调整使用播放器。Web/Android 当前使用系统 Web Speech 能力，不含这两个原生离线引擎。

项目不引入广告 SDK、内购或付费身份服务。各模型与预编译依赖的实际组成、固定版本和第三方许可见 [离线语音说明](offline-voice.md) 与 [第三方声明](../THIRD_PARTY_NOTICES.md)。

## 构建、部署与验证

Xcode 工程由仓库内 Python 脚本生成，签名配置仅保存在忽略的本地文件。Web 与 Android 共用 TypeScript 检查、测试和构建；公开 CI 使用临时 Android 调试签名，个人分发包在私有环境使用固定证书。

生产部署将静态 Web 与 API 放进限额 Node 容器，经独立 HTTPS 代理访问，账号数据库、原文件和证书均在镜像外持久化。变更只更新清读项目，保留上一兼容镜像和数据备份。运行入口见 [开发指南](development.md)、[部署维护基线](../web/deploy/DEPLOYMENT.md)；已测设备与未测范围见 [验证记录](verification.md)。

# 清读首版设计

日期：2026-10-20。

## 产品目标

用户希望在 iPhone 上输入书名，直接找到不同来源的小说，收藏并阅读，不想逐本寻找网址，不接受广告和会员门槛。选择原生 SwiftUI 客户端，自用安装；服务器和商店分发不是首版前提。

首版优先打通真实阅读链路，内置能核实的文本来源，另提供网站规则导入。热门连载来源的覆盖率、旧阅读书源兼容性和复杂网页解析是后续工作，不能用漂亮界面掩盖这部分差距。

## 模块边界

`ReadingCore` 是没有 SwiftUI 和持久化依赖的 Swift 包：来源声明、网络传输、搜索、目录与正文解析由它负责。每个来源把自己的结果映射到统一的 Book / Chapter / ChapterContent，界面不包含网站 CSS 选择器。

App 层在主线程管理可观察状态；搜索任务可取消，旧请求不得覆盖新查询。界面负责加载、空结果、部分失败与重试，而不把网络异常解释成没有这本书。

书架、阅读设置和章节内容分别持久化。章节缓存按书籍和章节稳定标识分开存放，阅读位置按文字锚点保存。清除正文缓存不清除书架和阅读进度。删除书籍只能影响该书的数据。

## 搜索与来源

请求从 iPhone 直接发往来源，不经开发者服务器转存。查询词由引擎编码。多来源并发查询，单个来源失败不使整次搜索失败；同书各来源保留可识别的出处。

内置来源用于实际验证基础能力，不代表覆盖全部网络小说。导入规则采用简单 CSS 声明；首版不运行第三方 JavaScript，也不声称兼容 Legado 的完整规则语言。需要执行 JavaScript 或登录的来源应单独设计，不隐式塞进解析器。

## 视觉与交互

纸张暖白、深墨色正文、朱红强调色；书架和阅读页面以内容为中心。标题用系统可用的衬线字形，正文支持调整字号和行距。使用系统导航、动态字体和可访问性标签；大字号、深色与横竖屏需要在模拟器和真机持续验证。

不引入广告 SDK、内购、账户系统、运营推荐流或伪造热门排行。无网络时仍可继续阅读缓存和本地样例。

## 安装和开发

Swift 包测试可以用 Command Line Tools 执行；原生 UI 构建需要完整 Xcode 与 iOS SDK。Xcode 工程由仓库内 Python 脚本生成，不要求安装额外项目生成器。

付费 Apple Developer 会员不是写代码或模拟器运行的前提。签名只在安装真机时配置，仓库不保存团队 ID、证书与密钥。

## 下一步

1. 真机确认文字位置恢复、键盘搜索、后台切换和系统字号。
2. 选择并验证用户常看的网络小说来源，增加相应适配与真实网页回归样本。
3. 按需增加书源兼容层、目录分页、批量离线下载和系统朗读。
4. 在来源覆盖稳定之后，再考虑多源结果归并、章节标题匹配和跨源阅读位置迁移。
